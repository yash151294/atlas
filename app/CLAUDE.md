# App layer

FastAPI in `app/main.py` and plain HTML pages with vanilla JS under `app/static/`: no framework, no build step. Three analyst tasks (Network, Research, Review, the last served by `app/static/documents.html`) and one governance page (Compliance). Requests never read storage: `store.cache()` (an in-memory DuckDB of the serving tables) answers reads in milliseconds, and the working files a document review needs (raw text, mentions, vault, review queue) are memoised by the store on OneLake until written or a run finishes elsewhere; writes go through `store` to `data/` or OneLake and refresh the cache; `_follow_pipeline_runs` polls the run manifest every five minutes so a scheduled run's output arrives without a restart; `warm_models` loads the reranker at startup.

## Conventions
- The application is Atlas and names no one else. Nothing an analyst or a visitor can see carries any other name or mark: not the lockup, the tab icon, the tab title, the landing copy, the page headlines or the Compliance prose (ADR 44). Everything a browser can show — view-source included — follows: the bootstrap object is `window.ATLAS`, the page-state keys are `atlas.network`, `atlas.research`, `atlas.review`, and the cookies are `atlas_s`, `atlas_state`, `atlas_next`.
- Identity: Entra auth-code flow (`/auth/login`, `/auth/callback`, a signed cookie `atlas_s` valid `SESSION_HOURS`). A visitor without a session is sent to the landing page `/welcome?next=<the page asked for>` (`app/static/landing.html`: the lockup, one line, Sign in with Microsoft); `/auth/login?next=` keeps the destination in a short `atlas_next` cookie and the callback returns there, `_safe_next` allowing only a path on this app. Without `ENTRA_*`, `/welcome` still renders so the page can be checked. Without `ENTRA_*` the app runs as `DEV_USER` (`analyst@atlas.local`). `REQUIRE_AUTH` (an OneLake root, or `ATLAS_REQUIRE_AUTH=1`, which the image sets) fails closed: 503 for everything except `/healthz` when sign-in is not configured. Every endpoint that records a decision takes `who: str = Depends(who)` and writes the UPN into the record. The sign-in callback also fetches the user's 48px profile photo from Microsoft Graph (`User.Read` covers it) into `PHOTOS`, process memory keyed by UPN, served by `/api/me/photo`; after a restart the header shows initials until the next sign-in.
- Mutations: every read-modify-write endpoint runs under `MUTATE`, one process-wide lock; the redacted table goes through `_load_red` and `_save_red`; `_log(name, **rec)` appends to a JSONL log (`audit_log.jsonl` for approvals, span and identity decisions and manual redactions; `vault_access.jsonl` for reveals; `access_log.jsonl` for sign-ins; retention, erasure and subject lookups write the retention log through `retention`). A subject lookup needs a `reason` (the request reference) the same way a reveal does.
- Reads: `q(sql)` over the cache, `records(df)` to JSON-safe dicts, `page(name, request)` for a static page with the signed-in user and the review-queue count inlined as `window.ATLAS` (the header is complete at first paint; `/api/me` and `/api/home` are the fallback when the page is opened without it). `/healthz` is the readiness probe: 503 until the cache holds the chunks. Responses over 1 KB are gzipped (Container Apps ingress does not compress). HTML is `no-store`; `/static` is `no-cache` (revalidated by ETag, so a deploy is never served stale even when `?v=` was not bumped); the Cytoscape script on Network is deferred and `draw()` waits for it.
- A contributor carries their Salesforce `Status__c`: anything but `Active` shows as a grey tag beside their base on Network (search results and profile) and on Home's 'who holds it', because their interviews stay in the network as history and only the label says they cannot be asked (ADR 46).
- Logs on the pages: Compliance lists them (Home shows none). Home is an analytics page over the serving tables: `/api/home` returns the counts, the gate (queue, the risk histogram at the 0.05 step the scores use, special-category flags) and `network.overview` (coverage by region and sector, the pace of interviews over 24 months, contributors by sources reached). The coverage matrix labels a cell with its source count and fills it by reach today (the sum of `network.recency`, the decay the Network search ranks by), so Home and Network agree on what reach means; a cell links to `/network?region=&sector=`, which the Network page reads into its filters (a link wins over the remembered state, as `?q=` does), a contributor's name to their profile, the gate card to Review. The page ends with one line: when the serving tables were last refreshed (the run manifest's `finished`). Removing a log row is a storage edit (rewrite the writer's partition), never an API.
- Network search tells you what it did with your words: a region or sector the query names is applied as a filter and named in the result line ("**Gulf** read from your search and applied as a filter, the rest ranked"), and each matched person's chips show the phrase of their indexed line the hit came from rather than the bare query word. The line carries topics, former organisations, region and seniority that the card never displays, so before this a match on a topic read as an unexplained chip against a descriptor not containing the word (ADR 42).
- Research threads are page-held: the page sends `history` with each question; nothing is stored server-side (ADR 25). The thread (questions and briefings as data, never revealed values) sits in the browser's localStorage under `atlas.research` until New thread, so it survives leaving the page; a question is written there as `pending` with the job id the page made for it, before it is sent, so leaving the desk mid-answer no longer drops the turn: the briefing runs in `ASKPOOL`, outliving the request that started it, and the next load restores the thread and reconnects to that job (`_ask_job` joins a run in flight, keyed by job id, the last eight rejoinable) rather than asking it again. One spinner per question, in the thread card beside its skeleton. Network keeps its query, filters, topics toggle and the open profile or source card under `atlas.network`, and Review its list tab, open document and view under `atlas.review`, both written on `pagehide`; a link with `?q=` or `?doc=` wins over them (ADR 34). The evidence panel's tokens are clickable: a reveal there goes through the same `/api/vault/reveal` as the Review page, logged against the passage's document. The checker's verdicts are on the surface, never only in the payload: the badge counts findings supported of findings written, a finding it cannot support is dimmed and carries `checker: <reason>`, and the headline is checked the same way (ADR 40) with its reason under whichever sentence the model wrote — under the headline normally, under the text headline when a computed network headline sits above it, since that one is never model-written. A network question (who can reach, how two people connect, who is within N hops) is classified by the planner and answered from the edge table by `network.traverse`: the headline and the Network block are computed and written as sentences (who connects whom, each step of a route with its date, direct connections and one step further; never a hop count), the findings below are what the passages say, a pure network question skips retrieval and the answer model, and every briefing that cites transcripts ends with who can re-approach those sources (`network.reach_of`), each name a link to the Network page (ADR 35).
- Front end (`app/static/app.js`): `$`, `esc`, `J` (GET JSON), `POST`, `fmtd`, `TOKRE`, `NAV`, `PLAIN` (detector, kind and action ids → plain words), `shell()` (header, nav, review count badge, the account menu: a native `<details>` with the avatar or initials and first name, opening to full name, UPN and sign-out), `reveal(token, doc_id)` (reason prompt, the vault call, the toast; Review and Research decorate their own tokens with the value), `mem` (guarded localStorage get, set, del), `tokenise`, `spinner`, `skeleton(el, n, msg)` (shimmering placeholder cards in the shape of what is coming), `toast`, `logRow`. Each page is `<body><script app.js><main>` plus one inline script: the script sits inside the body so `shell()` inserts the header before the first paint. `app/static/base.css` is the design system (ADR 36, 44): tokens on `:root`, the navy header with a mint underline on the active task, a light `h1` and one line of `.sub` on every page (no second label: the header already names the task), white cards with 16px corners, pill buttons and chips, 44px inputs, segmented `.tabs`, `.text` for the document panes and `.decision` for a review row (text left, buttons right, one line), the raw and retained panes as one `.panes` grid so their captions and text start level (`.panes.one` when only the retained copy is shown; a class, because Network's side panel also carries `id=side`), `.sk` skeletons, `.stagger` for lists that reveal in sequence, and motion that is one `rise` per page plus a cross-fade between pages (`@view-transition`), all switched off under `prefers-reduced-motion`. `/` focuses the search box on Network and the question box on Research. The header brand is the product lockup: `app/static/atlas-mark.svg` (a globe reduced to three parallels, with one point marked on the middle line) then the application's name, Atlas (ADR 38, 44); the mark is the only image the app ships, off-white on the navy header, and the word beside it is text so it scales and is read aloud. The landing panel carries the same `.lock` rule one size up, and the tab title is `Atlas · <page>`. `app/static/favicon.svg` is the same geometry scaled into a navy tile (the mark alone is off-white, so it would vanish on a light tab strip); every page links it in its own head beside the stylesheet rather than through `shell()`, so there is no flash of the default icon and no `/favicon.ico` miss before the script runs.
